# 台股綜合監控系統

自動掃描台股、綜合評分、Gmail 推播。附網頁介面與回測工具。

> **這是縮小研究範圍的篩選工具,不是買賣訊號系統,也不構成投資建議。**
> 通過篩選只代表「值得你花時間研究」,不代表該買。

### ⚠️ 跑模擬前一定要先稽核資料

```bash
python audit.py         # 檢查資料品質
python audit.py --fix   # 把嚴重錯誤的檔案移到 twdata_bad/
```

**回測結果只要有一檔股票的價格資料錯誤,整個結論就是垃圾。** 等權重平均對離群值極度敏感——一檔假裝漲了 30 倍的股票,就能讓 120 檔的平均報酬從 +200% 變成 +1000%。

yfinance 的台股資料在這些情況容易出錯:減資(台股特有)、大量股票股利、長期停牌後復牌、興櫃轉上市。

稽核會檢查:極端總報酬、單日異常跳動、零價負價、資料空窗、還原權值比例失真,並比較**平均數與中位數**——兩者差距大就代表有離群股主導。

### Python 3.13+ 的憑證問題

若出現這個錯誤:

```
ssl.SSLCertVerificationError: certificate verify failed:
Missing Subject Key Identifier
```

**原因**:Python 3.13 起,預設 SSL context 啟用了 `VERIFY_X509_STRICT`,嚴格檢查 RFC 5280 合規性。證交所的憑證缺少 Subject Key Identifier 欄位,3.12 以前會放行,3.13 之後被拒絕。這是 Python 刻意提高安全標準的結果,不是 bug。

**已處理**:`netutil.py` 會自動偵測並重試。診斷指令:

```bash
python netutil.py
```

會顯示你的 Python 版本、是否啟用嚴格模式,以及四個證交所端點是否可連。

**安全說明**:netutil 只移除 `VERIFY_X509_STRICT` 這一個旗標,而且**只對 twse.com.tw 等官方網域**。憑證鏈驗證、主機名稱檢查、有效期限檢查全部保留。這與 `ssl._create_unverified_context()`(關閉所有驗證、可被中間人攻擊)完全不同。

### 下載資料的注意事項

```bash
python backtest_tw.py --download        # 預設 120 檔
python backtest_tw.py --download 60     # 想快一點就少一點
python backtest_tw.py --verify          # 隨時檢查資料狀態
```

- **可中斷,重跑會自動接續**——已下載且完整的檔案會略過
- 證交所 API 不通時自動改用內建的 63 檔權值股備援清單
- 下載結束會回報成功/失敗檔數,失敗多於成功時建議重跑
- 少於 30 檔可用時會警告:統計意義有限

## 快速開始

```bash
pip install -r requirements.txt

# 0. 下載股價資料(必要,約 5 分鐘)
python backtest_tw.py --download     # 前 120 大個股,10 年
python backtest_tw.py --verify       # 檢查資料可用

# 1. 確認連線與資料源可用
python netutil.py                    # 先跑這個,檢查憑證與端點
python chips.py --check
python revenue.py --check

# 2. 回補籌碼歷史(約 5 分鐘,勿中斷)
python chips.py --backfill 90

# 3. 設定 Gmail
export GMAIL_APP_PASSWORD="你的16位應用程式密碼"
# 編輯 config.json 填入 username / to
python notify.py --test

# 4. 執行
python tw_stock_monitor_v2.py     # 命令列
streamlit run app.py              # 網頁介面
```

### Gmail 設定三步(順序不能反)

1. **開啟兩步驟驗證** — 沒開就產生不了應用程式密碼
2. **產生應用程式密碼** — https://myaccount.google.com/apppasswords
3. **設成環境變數** — 不要寫進 config.json

| 錯誤訊息 | 原因 |
|---|---|
| `認證失敗:535` | 用了一般登入密碼,或沒開兩步驟驗證 |
| `應用程式密碼長度為 N` | 不是 16 字元就不是應用程式密碼 |
| `連線被中斷` | 公司/學校網路擋 587 埠 → 改 `"smtp_port": 465` |

### 排程

cron 不載入 shell 設定檔,環境變數要寫在 crontab 裡:

```
GMAIL_APP_PASSWORD=abcdefghijklmnop
30 15 * * 1-5 cd /path/to/stock && /usr/bin/python3 tw_stock_monitor_v2.py >> run.log 2>&1
```

時間是 **15:30**,不是 14:30——三大法人資料收盤後才公布。

### 雲端自動化(GitHub Actions)

這個 repo 本身就設定了雲端排程,不需要自己的電腦開機:

| Workflow | 排程(台灣時間) | 做什麼 |
|---|---|---|
| `.github/workflows/daily-scan.yml` | 週一到週五 15:30 | 掃描 + 寄信,`chips.db`/`trades.db` 存 Google Drive |
| `.github/workflows/news-crawler.yml` | 每天 08:00、20:00 | `news/` 底下的新聞爬蟲,`news/news.db` 也存 Google Drive |

**設定方式**(在 repo 的 Settings → Secrets and variables → Actions 新增):

| Secret | 內容 |
|---|---|
| `GMAIL_APP_PASSWORD` | Gmail 應用程式密碼 |
| `CONFIG_LOCAL_JSON` | 本機 `config.local.json` 的完整內容(watchlist / 持股 / 收件信箱,不進 git) |
| `NEWS_ENV_FILE` | 本機 `news/.env` 的完整內容(LLM 金鑰 / Gmail / 收件信箱) |
| `GDRIVE_CLIENT_ID` / `GDRIVE_CLIENT_SECRET` / `GDRIVE_REFRESH_TOKEN` | 見下方「Google Drive 持久化」 |

**Google Drive 持久化**:GitHub Actions 每次都是全新環境,`chips.db`、`trades.db`、`news/news.db` 這些會累積的資料庫,靠 `gdrive_sync.py` 在執行前後從你自己的 Google Drive 下載/上傳(用 OAuth 使用者授權,不是 service account——service account 沒有自己的儲存空間配額,建不了檔案)。一次性設定:

```bash
python gdrive_authorize.py path/to/client_secret.json
```

跑完把印出的 3 個值存成上面那 3 個 Secrets。詳細步驟(含 Google Cloud Console 操作)見 `gdrive_authorize.py` 開頭的說明。

**網頁版(Streamlit Community Cloud)**:`app.py` 部署在 [share.streamlit.io](https://share.streamlit.io),同樣需要那 3 個 `GDRIVE_*` 值,但是存在 **Streamlit 自己的 App settings → Secrets**(跟 GitHub Secrets 是兩個獨立系統,要分別設定),格式是 TOML:

```toml
GDRIVE_CLIENT_ID = "..."
GDRIVE_CLIENT_SECRET = "..."
GDRIVE_REFRESH_TOKEN = "..."
```

網頁版只從 Drive **下載**、不會上傳——GitHub Actions 才是資料的唯一寫入者,避免兩邊同時寫造成衝突。

## 功能總覽

### 選股池
- 自動掃描全上市(依成交金額前 N 大),或自訂 watchlist
- 基本面預篩後才下載歷史,節省請求量

### 技術面
- RSI(14)、KD(9,3,3 台股慣用平滑)、MACD(12,26,9)、ATR(14)
- 均線 5/20/50/60/150/200
- **O'Neil RS 評等** — 加權報酬的橫斷面百分位(2×最近季 + 前三季)
- **Minervini 趨勢模板** — 8 條件逐項檢視
- **Weinstein 四階段** — 30 週線位置與斜率

### 籌碼面
- 外資買賣超:連續天數、5/20 日累計、佔成交量比重
- 投信買賣超:連續天數、5 日累計
- 融資餘額 5 日變化(反向指標)
- **自營商刻意排除** — 多為權證避險部位,無方向性意義

### 基本面
- 月營收年增率、連續成長月數、成長是否加速
- 本益比、殖利率、股價淨值比

### 風險
- 2×ATR 停損參考價、年化波動率
- 追高、高波動、跌破月線、外資連賣、融資暴增 → 扣分
- 持股出場提醒(跌破月線/季線/虧損逾 10%)

### 機率區間
- 20 日與 60 日的 50%/70%/90% 價格區間
- 區間可信度 0–100
- 結構性支撐壓力(含測試次數)

### 通知與介面
- Gmail HTML 信件(分數色階、逐項加分扣分)
- Telegram(預設關閉,可並存)
- 終端機輸出、CSV 存檔
- Streamlit 網頁:結果表、個股頁、K線疊機率區間扇形、即時調整門檻

### 回測
- 分數分組的未來報酬 vs 基準
- 單一條件貢獻度拆解
- 重疊樣本修正、年度穩定性、尾部風險

## 評分方式

滿分 100。每項是**通過給滿分、不通過給 0** 的二元判斷。

**技術面 50**

| 條件 | 分 |
|---|---|
| 年線上揚**且**股價在其上 | 14 |
| RS 評等 ≥70 | 11 |
| RSI 落在 35–58 | 10 |
| KD 低檔交叉 **或** MACD 翻正 | 8 |
| 月線 > 季線 > 年線 | 7 |

**籌碼面 29**(2026-09 依 657 日台股實測重配)

| 條件 | 分 | 證據 |
|---|---|---|
| 外資 5 日買超佔成交量 >5% | **14** | p=0.0023,樣本外兩組皆顯著 |
| 外資連續買超 ≥3 日 | 9 | p=0.0086,樣本外一組顯著 |
| 融資減 >3% 但股價守住月線 | 6 | 待驗(資料修復中) |
| ~~外資 5 日買超絕對金額~~ | ~~7~~ | 移除:樣本外不顯著,且與佔量重複 |
| ~~投信買超~~ | ~~7~~ | **移除:方向可能相反**(p=0.062,樣本外一組 −2.27%) |

**偏離度 15**(新增)

| 條件 | 分 | 證據 |
|---|---|---|
| 乖離分位 ≤25(未過度延伸) | 15 | p=0.0020,樣本外雙組複製 |
| 乖離分位 ≥90(過度延伸) | −10 | 同上 |

**月營收 15** — 年增 >10%(7)、連 3 月正成長(5)、成長加速(3)

**估值 5** — 本益比 ≤20 **或** 殖利率 ≥3%

**扣分 最多 −56** — 外資連 3 賣(−12)、跌破月線(−10)、營收連 3 月衰退且年減 >15%(−10)、融資暴增但股價未創高(−8)、貼近年高(−8)、ATR >5%(−8)

### 兩種計分法(報告以備註呈現)

**加總式**(預設):各支柱直接相加。問題是沒有交互作用——「趨勢爛但籌碼好」與「樣樣普通」可能同分,但意義完全不同。

**閘門式**(同時計算,以備註顯示):技術面當作 0.25–1.0 的乘數。趨勢不成立時,籌碼與營收的分數會被打折。

```
閘門 = clip(技術得分 ÷ 技術滿分, 0.25, 1.0)
閘門分 = (技術得分 + 其他得分 × 閘門) ÷ 總滿分 × 100 + 扣分
```

兩者差距超過 4 分時,報告會加註一行:

```
※ 閘門式 52 分(低 15):技術面僅 32/50,籌碼營收被打折 0.64
```

實測對照(籌碼與營收條件完全相同,只有技術面不同):

| 情境 | 技術 | 加總式 | 閘門式 | 閘門 |
|---|---|---|---|---|
| 技術面強勢 | 32/50 | 67 | 52 | ×0.64 |
| 技術面疲弱 | 21/50 | 48 | 27 | ×0.42 |

**兩種都沒有經過驗證,哪個比較好是未知的。** 併列顯示是為了讓你看見差異,不是要你相信閘門式比較對。

## 模擬交易

兩種模式,**不要混淆**:

| 模式 | 做法 | 誠實度 |
|---|---|---|
| **紙上交易** (`trading.py`) | 每天記錄訊號,隔天用真實開盤價成交,往前累積 | ✅ 無前視偏差,唯一誠實的驗證 |
| **歷史模擬** (`simulate.py`) | 用歷史資料快速跑完整策略 | ⚠️ 快,但看完結果改參數就已污染 |

紙上交易隨主程式每日自動執行,結果附在報告末端。歷史模擬手動跑。

### 真實交易成本(台股 2026)

```
手續費 0.1425% × 6折 × 買賣兩次  = 0.171%
證交稅 0.3%(賣出)              = 0.300%
滑價   0.1% × 兩次               = 0.200%
                          來回總計 = 0.671%
```

年周轉 4 次 = 年成本 2.7%。**一個「超額報酬 +0.6%」的策略在成本後是虧的。**

### 實測結果:出場規則比進場規則重要得多

87 檔真實股價、4.9 年、含全部成本:

| 出場設定 | 年化 | 回撤 | 交易數 | 平均持有 | 期望值 |
|---|---|---|---|---|---|
| 跌破月線即出 | **−19.40%** | −66.5% | 2319 | 4 天 | −0.56% |
| 關掉月線出場 | +4.36% | −14.7% | 497 | 29 天 | +0.57% |
| 再放寬分數門檻 | +5.72% | −12.4% | 371 | 39 天 | +0.90% |
| 再放寬停損至 3ATR | +4.80% | −14.2% | 278 | 51 天 | +0.94% |
| 再延長持有上限 | **+9.30%** | −14.4% | 188 | 73 天 | +2.13% |

**同一個進場邏輯,只改出場規則,年化差 28 個百分點。**

「跌破月線就出場」聽起來很合理,實際上在震盪時瘋狂進出,2319 筆交易光成本就吃掉一切。所以 `exit_below_ma20` **預設關閉**。

### 但最重要的結果是這個

```
策略(最佳設定)   年化 +8.97%   回撤 -15.58%   夏普 0.84
等權重買入持有     年化 +16.47%  回撤 -11.53%   夏普 1.37

判定:策略年化輸買入持有 7.50 個百分點。
      買入持有更省事、成本更低、稅負更少。
```

**報酬更低,回撤更大,夏普更差。** 三個維度全輸。

這是整個專案裡最該正視的數字。前面所有回測都只算「訊號後的平均報酬」,那不是績效——加上資金限制、部位大小、停損執行和真實成本之後,結論反過來了。

同樣的限制依然適用:美股不是台股,2012–2017 是一段強勁多頭(買入持有本來就難贏),沒有納入籌碼與營收。但**在這份資料上,結論很清楚**。

### 用法

```bash
python simulate.py              # 歷史模擬 + 買入持有對照
```

紙上交易在 `config.json` 的 `paper` 區塊設定,隨主程式自動執行。累積數月後報告會顯示:

```
【paper 績效】23 筆已平倉,7 檔持有中
  總損益      +34,210 元(+3.42%)
  期望值      每筆 +1.49%   ← 比勝率重要
  勝率        43.5%  (平均賺 +6.20% / 平均賠 -2.15%)
  獲利因子    1.72  (>1.5 才算穩健)
  交易成本    每次來回 0.671%,累計約 15,433 元
```

**期望值比勝率重要。** 勝率 30% 但賺賠比 3:1 的策略,遠優於勝率 70% 但賺賠比 1:3 的策略。

## 產業分析

### 三個層次

**1. 官方分類** — 證交所 33 種產業別,來自月營收資料的「產業別」欄位。權威但粒度粗:「半導體業」裡有台積電也有小型 IC 設計。

科技相關(10 種):半導體業、電腦及週邊設備業、光電業、通信網路業、電子零組件業、電子通路業、資訊服務業、其他電子業、電子工業、數位雲端

泛科技(3 種,受同樣景氣循環影響):電機機械、電器電纜、綠能環保

**2. 相關族群** — 用日報酬相關性從資料裡發現實際共同波動的群組。

**刻意不寫死供應鏈對照表。** 那是靜態知識會過時,台股供應鏈重組也很快。共同波動是市場對「這些公司受同一因素影響」的實際定價。

驗證:對 87 檔美股跑這個方法,**完全不給產業標籤**,結果精準還原了實際產業——

```
族群2 (相關0.72)  EXC、NEE、PCG、PPL、SO、SRE    → 全部是公用事業
族群3 (相關0.76)  BAC、BRK-A、C、JPM、WFC        → 全部是銀行
族群5 (相關0.66)  BP、CVX、RDS-B、TOT            → 全部是石油
族群6 (相關0.56)  ABBV、AMGN、MRK、PFE           → 全部是製藥
```

**3. 同業排名** — 個股分數在自己產業內的百分位。

**跨產業比分數沒有意義。** 景氣循環股與成長股的合理分數區間本來就不同,航運股 45 分可能比半導體股 65 分更值得看。

### 產業熱度

熱度 = RS 中位數、市場廣度(多少比例站上季線)、營收年增 三項橫斷面排名的平均。

```
產業            類型   檔數  熱度   RS   廣度   營收年增    外資5日
半導體業          科技     4   83   63   75%   +27.5%    +8000
電腦及週邊設備業     科技     3   67   70   67%   +19.0%    +6000
```

## 潛力股篩選

定義寫在程式碼裡,不藏在黑盒子:

| 條件 | 理由 |
|---|---|
| 產業熱度 ≥ 60 | 產業本身要有動能 |
| 同業排名 ≥ 60 百分位 | 在自己產業裡是前段班 |
| **乖離分位 ≤ 75** | **尚未過度延伸** |
| 營收年增 > 0 | 基本面不在衰退 |

**第三條是關鍵。** 它排除已經噴出的標的,用的是本專案**唯一通過樣本外顯著性檢定**的發現(乖離分位高 → 未來報酬明顯較差,p=0.0020)。

其他三條都沒有經過檢定,是基於邏輯的設計。

只想看科技股就在 `config.json` 設 `"tech_only": true`。

### 「潛力」兩個字的意思

這裡的潛力**不是預測會漲**,而是「產業有動能、公司在同業前段、股價還沒噴出、營收還在成長」——四個條件的交集。

它仍然是篩選,不是推薦。程式看不到:公司在做什麼、客戶集中度、有沒有訴訟、產能開出時程、老闆誠不誠實。**那些才是決定潛力的東西。**

## 股價偏離標記

「折溢價」需要基準。個股沒有淨值(那是 ETF 和封閉式基金的概念),所以提供三種:

| 基準 | 意義 |
|---|---|
| **乖離率** | 相對自身均線。純技術,不假設合理價 |
| **乖離分位** | 相對該股**自己的歷史乖離分布**。解決跨股不可比——10% 乖離對台積電是異常,對高波動小型股是家常便飯 |
| **同業估值折溢價** | 本益比相對同產業中位數。最接近「貴/便宜」的直覺 |

七級分類,以自身歷史分位為準:

| 分位 | 分級 | |
|---|---|---|
| ≥98% | 極度溢價 | 🔴 |
| ≥90% | 顯著溢價 | 🟠 |
| ≥75% | 偏高 | 🟡 |
| 25–75% | 正常 | ⚪ |
| ≤25% | 偏低 | 🟢 |
| ≤10% | 顯著折價 | 🔵 |
| ≤2% | 極度折價 | 🟣 |

20/60/200 日三個天期同時計算,**三個天期同向才是真正的極端**。報告範例:

```
🔴 股價極度溢價 — 20日乖離 +7.7%(自身歷史第 99 分位)
   60日乖離 +14.8%(第 100 分位),回到季線需 -12.9%
同業溢價 +64.7% — 本益比 28.0 vs 半導體業中位數 17.0(6檔)
```

### 實測:這是唯一通過顯著性檢定的東西

85 檔真實股價、不重疊樣本、無前視偏差:

| 20日乖離分級 | 樣本 | 平均乖離 | 未來60日報酬 | 超額 | 勝率 |
|---|---|---|---|---|---|
| 顯著折價 | 60 | −4.4% | +6.26% | **+2.02%** | 78.3% |
| 偏低 | 107 | −2.3% | +5.46% | +1.22% | 74.8% |
| 正常 | 299 | +0.4% | +4.36% | +0.12% | 67.2% |
| 偏高 | 103 | +3.2% | +2.98% | −1.26% | 66.0% |
| 顯著溢價 | 78 | +4.9% | +1.56% | **−2.67%** | 61.5% |

**完全單調。** 統計檢定:

```
折價 vs 溢價:差 +3.97%,p=0.0020 ✓顯著
等級相關:rho=-0.155,p=0.00005
樣本外 A組:+4.11%(p=0.019)
樣本外 B組:+3.68%(p=0.056)
```

兩組獨立股票的方向與幅度都複製成功。這是本專案中**唯一**通過樣本外顯著性檢定的發現。

### 已於 2026-09 納入評分

原本因與趨勢因子方向矛盾而不計分,但它是本專案證據最強的因子(唯一在美股與台股兩份資料上都站得住的),所以改為**獨立支柱**計分 —— 不混進技術面,保留兩個透鏡的張力。

原本不併入的理由如下,仍值得理解:

**因為它與主評分互相矛盾。**

- 主評分獎勵強勢:年線上揚 +14、RS≥70 +11
- 偏離發現獎勵弱勢:折價組報酬明顯較高

這是兩個相反的賭注。把矛盾的訊號加總,只會得到一個內部不一致的模型——分數會互相抵銷,最後什麼都篩不出來。

所以偏離度是**獨立的第二個透鏡**,與分數併列呈現。你自己判斷這檔是「強勢股回檔」還是「弱勢股反彈」——那需要看基本面,程式判斷不了。

### 重要警告

**這個結果與先前「趨勢濾網表現不佳」出自同一份資料。** 兩者都指向同一件事:2012–2017 美股大型股是**均值回歸主導**的環境。

那是**一個**市場環境。動能因子在其他期間有效正是眾所周知的事,否則它不會是文獻裡的經典因子。**換個環境這個結論可能整個翻轉。**

偏離大不代表會回歸。高乖離可能是頭部,也可能是趨勢起點。

## 產業分類與科技相關篩選

### 「低股價」是個陷阱

**絕對股價高低沒有意義。** 20 元的股票不比 1000 元的便宜——股價只是市值除以股數,而股數是公司自己決定的。台積電拆股十次會變成 100 元,公司一點也沒變便宜。

所以 `sector.py` **不用絕對股價篩選**,改用三個相對定義:

| 條件 | 地位 | 依據 |
|---|---|---|
| **自身乖離折價** | ★主要 | 唯一通過樣本外顯著性檢定的維度 |
| 同業估值折價 | 輔助 | 實測未通過檢定(p=0.43),僅作標籤 |
| 排除營收衰退 | 濾網 | 避免價值陷阱 |

### 實測:同業維度沒有加值

用報酬相關性分群當產業代理(8 群,每群 5–20 檔):

```
自身歷史乖離   折價 +5.76% vs 溢價 +1.71%   差 +4.05%   p=0.0686
同業相對乖離   折價 +3.70% vs 溢價 +2.33%   差 +1.37%   p=0.4257 ✗
```

**沒有證據顯示同業相對估值能預測報酬。** 所以排序以自身乖離為主鍵,同業折價只當輔助標籤。

⚠️ 這個檢定用的是美股相關性分群,不是真實產業。台股的產業有實際供應鏈連結,結構性比相關性分群強得多,結論未必適用。但在有台股資料驗證之前,不該假設它有效。

### 產業分類

證交所 33 個產業別,歸為四大類:

- **科技核心** — 半導體、電腦週邊、光電、通信網路、電子零組件、電子通路、資訊服務、其他電子、數位雲端
- **科技連動** — 電機機械、電器電纜、化學工業、航運業
- **金融** — 金融保險
- **傳產/其他**

供應鏈位置標記(上游/中游/下游),以及景氣連動關係:

```
半導體業 → 電子零組件業、電腦及週邊設備業、光電業
通信網路業 → 資訊服務業、數位雲端
```

### 報告範例

```
【產業分布】
  ◆ 科技核心
    半導體業        12檔  均分  58.3  本益比中位  19.5  營收年增均  22.1

【科技相關:同業相對折價標的】
  (★ = 已驗證維度;非絕對股價;已排除營收衰退者)

  2342.TW 公司42 — 光電業 [中游]
    ★乖離第23分位 / 同業折價 -38%
    收盤 90.1 | 本益比 16.2 | 營收年增 43.7% | 綜合分數 48
    下游連動:電腦及週邊設備業、其他電子業

【⚠ 價值陷阱警示】
  以下標的估值與乖離都顯示便宜,但營收正在衰退。
    2320.TW 公司20 — 通信網路業  營收年增 -26.7%  同業折價 -31%
```

### 這不是「潛力」

程式找得出「相對便宜且營收未衰退」,但**找不出潛力**。潛力需要判斷公司在做什麼、產品競爭力、客戶集中度、技術護城河——這些程式全都看不到。

產業分類的真正價值是**整理與導航**,幫你理解手上這批標的分布在哪裡,而不是產生訊號。

### 資料缺漏的處理

```
分數 = (拿到的分 ÷ 有資料的項目總分) × 100 + 扣分
```

**「沒有資料」不等於「表現差」。** 上櫃股沒有證交所籌碼資料,剛安裝時沒有營收歷史——這些股票不該因此被判定為差。報告會標示覆蓋率,例如 `6488.TWO 59 分(資料覆蓋 55%,缺籌碼/營收)`。

覆蓋率低的分數是從較少證據推出來的,可靠度較低。

## 機率區間

**沒有「目標價」。** 從技術面推導單一目標價,準確度接近擲骰子;那是把一個寬到沒有意義的分配壓縮成一個點,丟掉最重要的資訊——不確定性。

方法是**過濾式歷史模擬**:取過去 2 年的 N 日報酬分配(非參數,自動處理厚尾),用當前波動率縮放,再套經驗校準係數取分位數。

### 校準結果(85 檔真實股價,樣本外驗證)

係數在 43 檔訓練股票上擬合,42 檔測試股票上驗證:

| 天期 | 係數 | 宣稱 50% | 宣稱 70% | 宣稱 90% |
|---|---|---|---|---|
| 20 日 | ×1.10 | 實際 49.9% | 實際 69.7% | 實際 87.3% |
| 60 日 | ×1.25 | 實際 50.9% | 實際 70.6% | 實際 85.6% |
| 120 日 | — | **不提供** | | |

為何需要膨脹係數:2 年歷史只含約 8 個獨立的 60 日期間,經驗分位數會系統性低估尾部。

**120 日以上已停用。** 調到搜尋上限後,最佳結果仍是宣稱 90% 實際僅 78%。修不好的東西不該給,呼叫會直接丟出例外。

支撐壓力標示測試次數,但**測試 3 次不代表第 4 次會守住**——那是描述歷史,不是預測未來。

## 驗證結果

以下用 87 檔美股、2012–2017、85,759 個股票日測試,評分函式與主程式相同,無前視偏差。

### 綜合分數

| 分數 | 樣本 | 60 日報酬 | 超額 |
|---|---|---|---|
| 基準(隨機買) | 85,759 | +3.21% | — |
| 60–69 | 4,147 | +3.81% | +0.61% |
| 70–79 | 672 | +3.70% | +0.50% |

**但這個顯著性是假的。** 60 日視窗互相重疊,有效獨立樣本只有約 1,429 個,t 值被高估 7.7 倍。改用不重疊樣本後:

```
≥55 分:p=0.649 ✗不顯著
≥60 分:p=0.504 ✗不顯著
```

**優勢消失。**

### 交易員模板高度重疊

| 訊號 | 觸發率 | 成立時 | 不成立 | 差距 |
|---|---|---|---|---|
| Minervini | 13.2% | 2.66% | 3.76% | −1.10% |
| Weinstein 第2階段 | 51.8% | 3.08% | 4.19% | −1.12% |
| RS ≥70 | 23.4% | 2.85% | 3.85% | −1.00% |
| v1 趨勢條件 | 45.0% | 2.99% | 4.12% | −1.13% |

四者差距幾乎一模一樣,不是巧合:

```
Weinstein ∩ v1趨勢    重疊 71%
Minervini ∩ RS≥70     重疊 56%
```

**把四個都加分不是集思廣益,是把同一個賭注押四次。** 所以模板只當標籤,不計入分數。

### 尾部風險

即使達標,60 日內虧損 >10% 的機率仍有 **6.4%**,與隨機買幾乎無異。**篩選沒有降低尾部風險。**

### 這份驗證的限制

美股不是台股;只涵蓋一段多頭;資料集是「2017 年仍存活的大型股」,有生存者偏誤;籌碼與營收完全沒驗證到。

**結論不是「策略無效」,而是「有效性未被證實」。** 差別很重要,但實務含意一樣:別把它當訊號機。

## 已知限制

1. **權重是手設的。** 用 `optimize.py` 可以換成有根據的值,但它內建五道防護,大多數情況下會告訴你「資料不足以支持調整,維持原樣」。**這是正確行為,不是失敗。**

2. ~~加總是線性的,沒有交互作用。~~ **已實作閘門式計分**,以備註併列顯示。但兩種計分法都未經驗證。

3. **籌碼歷史需自行累積,但可回補十三年。** T86 資料自 2012-05-02 起提供:
   `python chips.py --backfill 20200101`(可中斷,重跑自動接續)

4. **回測只涵蓋 v1 評分。** `backtest_tw.py` 測的是技術面分數,**籌碼與營收的貢獻完全沒被驗證過**——那部分目前是基於邏輯的設計,不是驗證過的結論。

5. **月營收只有快照。** OpenAPI 不提供歷史,每月執行累積。剛安裝時算不出趨勢,程式會警告。

6. **上櫃股籌碼不完整。** 證交所資料只涵蓋上市,`.TWO` 會缺籌碼分數(已由覆蓋率機制處理)。

7. **資料源會壞。** yfinance 是非官方 API,跑失敗是正常的,看 `run.log`。

8. **營收不等於獲利。** 毛利率崩掉照樣能營收成長。金控與控股公司的「營收」與製造業不可比。


`optimize.py` 強制五道紀律,不能關閉:

| 紀律 | 作用 |
|---|---|
| 股票切分 | 一半訓練、一半測試,測試集絕不參與最佳化 |
| 時間切分 | 前 70% 時間訓練、後 30% 測試 |
| 粗網格 | 權重只能取 {0,5,10,15,20},解析度越細越容易擬合雜訊 |
| 落差警告 | 訓練與測試差距過大時判定「過度擬合」並拒絕採用 |
| 基準對照 | 一律與「等權重」比較。贏不過等權重就建議用等權重 |

我用 87 檔美股實跑過一次,結果是:

```
權重方案            訓練集     測試集      落差         判定
原始(手設)        +0.40    -0.27    +0.67    ✗ 測試集無效
等權重             +0.63    -0.29    +0.92    ✗ 測試集無效
最佳化後           +0.76    -0.04    +0.80    ✗ 測試集無效

結論:沒有任何一組權重通過測試集驗證。
```

**訓練集從 +0.40% 進步到 +0.76%,測試集卻是 −0.04%。** 這就是過度擬合的樣子,工具正確地拒絕推薦它。

如果你跑出來也是這個結果,不要調參數硬要它通過——那是在騙自己。

## 使用前的四件事

1. **不要看到分數高就買。** 至少再看:公司在做什麼、有無重大消息、財報有無問題、產業景氣。程式看不到這些。
2. **一定要設停損。** 任何策略都會連續看錯,活下來比看對重要。
3. **分數低不代表不好。** 剛起漲常因「貼近年高」被扣分;長期下跌可能因 RSI 低而拿到回檔分。扣分項要和趨勢條件一起看。
4. **先自己回測再調權重。** 別信我設的數字。
